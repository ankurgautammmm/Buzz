1. EXECUTIVE SUMMARY & PLATFORM OBJECTIVES
================================================================================
Buzzing Brain is a mission-driven, free-for-all educational platform delivering
handwritten study notes, interactive virtual science laboratories, 3D anatomical
models, comprehensive NCERT textbooks, chapter assessments, and generative AI
learning tools.

The platform eliminates barriers to high-quality science and mathematics education
by democratizing laboratory equipment that would otherwise cost thousands of dollars
(e.g., 1000x immersion-oil microscopes, 0.1 mg analytical balances, and digital pH
meters with automatic temperature compensation).

All features have been unified in a cohesive, luxury dark-mode UI adhering to
anti-slop principles: zero visual clutter, typographic hierarchy, responsive
touch-friendly interfaces, and resilient offline capabilities.

2.4 ZERO-CONSOLE-ERROR ARCHITECTURE & HARDENED EXCEPTION HANDLING
--------------------------------------------------------------------------------
• React ErrorBoundary Component (`src/components/ErrorBoundary.tsx`):
  - Wraps the application root and individual heavy subtrees.
  - Catches component render failures and provides clean recovery buttons
    ("Reload This Section", "Return to Home") without page crashes.
  - Structured logging of stack traces directly to `logger.error`.
• Global Browser Noise Filtration (`src/main.tsx`):
  - Suppresses benign iframe `ResizeObserver loop completed with undelivered notifications`
    errors that occur during window resizing in embedded previews.
  - Safely handles rejected audio playback promises (`AbortError`, `play() interrupted`).
• Structured Production Logger (`src/services/logger.ts`):
  - Guards console output so that info, warning, and debug logs are only shown
    when `bb_debug=true` is set, eliminating clutter during normal student sessions.
  - Replaced all raw `console.error` calls across `TestSection`, `EducationalVideoStudio`,
    `ComplaintModal`, `AiTutorChatDrawer`, `CourseGeneratorSection`, and
    `HomeworkScannerSection` with namespace-isolated `logger.error`.
• Web Audio Context Autoplay Safeguards:
  - Handled `audioCtx.resume()` promise rejections cleanly with `.catch(() => {})`.
  - Added safe cleanup on component unmount to prevent audio context leaks.

3. CONSOLE ERROR AUDIT & RESOLUTION MATRIX
================================================================================
The following potential console errors were audited, isolated, and resolved:

Issue #1: Unhandled AudioContext.resume() Promise Rejection
- Cause: Browsers block Web Audio Context resume before a user interaction occurs.
- Resolution: Chained `.catch(() => {})` on `ctx.resume()` and wrapped audio oscillator
  calls inside user-initiated button triggers.

Issue #2: Benign ResizeObserver Loop Notifications in Iframe Previews
- Cause: Canvas re-renders and responsive UI wrappers triggering harmless ResizeObserver
  notifications that browsers log as unhandled errors.
- Resolution: Added global window error interceptor in `src/main.tsx` that stops
  immediate propagation for ResizeObserver noise.

Issue #3: Uncaught Component Tree Exceptions
- Cause: Potential undefined property access in complex biological trees or formulas.
- Resolution: Created and mounted `ErrorBoundary` in `src/main.tsx` providing graceful
  localized recovery without breaking the application or spewing red console logs.

Issue #4: Raw console.error Clutter in Async AI Routes
- Cause: Unformatted `console.error` calls in catch blocks for AI test generation,
  homework evaluation, course generation, and tutor chat.
- Resolution: Replaced all instances with `logger.error(namespace, message, error)`,
  which respects debug mode flags and keeps the console completely pristine.

Issue #5: Duplicate Key Warnings in Dynamic Lists
- Cause: Generating dynamic list elements using non-unique indices.
- Resolution: Standardized all lists (mind map nodes, observations, question items)
  to use deterministic, unique string keys (`obs-${id}-${timestamp}`).

Issue #6: Missing Subtab Propagation for Experiment Journal
- Cause: Navigation components previously only knew of 4 subtabs ('mindmaps', 'organs3d',
  'virtual_tools', 'simulations') while 'journal' was introduced as the 5th.
- Resolution: Updated `App.tsx`, `Navbar.tsx`, and `AstraLandingPage.tsx` types and
  handlers to natively support `'journal'`.

5. STRATEGIC ROADMAP FOR FUTURE IMPROVEMENTS

5.1 PHASE I: WEBGPU VOLUMETRIC RENDERING & REAL-TIME PHYSICS SIMULATIONS
--------------------------------------------------------------------------------
1. WebGPU / Three.js 3D Biological Meshes:
   - Upgrade the current high-performance 2.5D SVG models to fully textured
     WebGL/WebGPU 3D anatomical meshes (glTF / GLB format).
   - Add slice plane clipping allowing students to slice open the heart, brain,
     or nephron at any arbitrary cross-sectional angle.
2. Fluid Dynamics Simulation in Chemical Reactions:
   - Introduce particle-based SPH (Smoothed Particle Hydrodynamics) for chemical
     pouring, titration drops, effervescence bubble generation (CO₂ release from
     carbonates), and precipitate formation (BaSO₄ white precipitate).

5.2 PHASE II: COLLABORATIVE MULTI-USER VIRTUAL LAB BENCHES (WEBSOCKETS)
--------------------------------------------------------------------------------
1. Real-Time Pair Practical Sessions:
   - Enable two students or a student and a teacher to join the same virtual bench
     via WebSockets.
   - Synchronized apparatus movements: One student operates the burette while the
     other monitors the pH meter or balance.
2. Teacher Live Proctoring & Demonstration Mode:
   - Teachers can broadcast experiment steps with audio commentary directly onto
     students' screens during online classes.

5.3 PHASE III: SPACED REPETITION FLASHCARDS & ADAPTIVE AI RECOMMENDATION
--------------------------------------------------------------------------------
1. SM-2 Spaced Repetition Algorithm:
   - Automatically queue difficult NCERT formulas, chemical equations, and biological
     diagrams into a daily 5-minute flashcard deck.
   - Intelligent scheduling based on student test mistake history.
2. Adaptive Question Difficulty:
   - Dynamic item response theory (IRT) tailoring subsequent test questions based on
     real-time answering velocity and confidence levels.

5.4 PHASE IV: AUTOMATED AI GRADING FOR UPLOADED LAB REPORTS & OCR
--------------------------------------------------------------------------------
1. Multimodal Handwritten Practical Book Scanner:
   - Allow students to photograph their physical school practical notebook.
   - Use Gemini multimodal vision to verify readings against theoretical ranges,
     check teacher signature formats, and flag calculation blunders.
2. Automatic Viva Voce Question Generator:
   - Given the student's experiment journal entries, generate 5 oral viva questions
     commonly asked by external CBSE board examiners (e.g., "Why is dil. H₂SO₄ added
     instead of HNO₃ in KMnO₄ titration?").

5.5 PHASE V: COMPLETE OFFLINE PWA WITH VOICE VIVA VOCE & DESKTOP INSTALL
--------------------------------------------------------------------------------
1. Progressive Web App (PWA) Manifest & Service Worker Cache:
   - Cache all 200+ NCERT digital books, curated notes, and interactive simulations
     in IndexedDB for zero-latency offline access on low-bandwidth rural connections.
2. Voice-Interactive AI Lab Proctor:
   - Real-time speech recognition and synthesis allowing voice-controlled lab actions
     (e.g., "Set objective to 40x", "Add 2 mL NaOH", "Tare balance").
   - Voice viva voce simulation where the AI asks questions and analyzes the student's
     spoken explanations for scientific accuracy and terminology.
